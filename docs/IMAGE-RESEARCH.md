# Bean Wiki 이미지 리서치·라이선스 정책

아티클의 사진과 도해는 장식이 아니라 **시각 근거**입니다. 이 문서는
`image-researcher`가 후보를 검색하고 아티클에 적용할 때 지켜야 할 운영 계약입니다.
법률 자문을 대체하지 않으며, 권리가 불명확하면 사용하지 않는 것이 기본값입니다.

## 1. 허용 범위

자동 수집·적용 후보는 다음 라이선스만 허용합니다.

| 라이선스 | 자동 후보 | 필수 조치 |
|---|---|---|
| CC0 / Public Domain | 허용 | 출처와 알려진 제작자를 기록 |
| CC BY | 허용 | 제작자·라이선스·원본 링크·변경 여부 표시 |
| CC BY-SA | 허용 | CC BY 의무 + 변형본을 동일/호환 라이선스로 유지 |
| CC BY-NC 계열 | 금지 | 상업성 판단 없이 자동 사용하지 않음 |
| CC BY-ND 계열 | 금지 | 리사이즈·크롭·재배치 위험이 있어 자동 사용하지 않음 |
| Fair use / 불명확 / All rights reserved | 금지 | 공식 원문 링크만 제안 |

라이선스만으로 인물권, 상표권, 사생활, 문화재 촬영 제한이 해결되지는 않습니다.
식별 가능한 인물이나 브랜드가 핵심 피사체인 후보는 별도 사람 검토가 필요합니다.

## 2. 검색 소스

### 자동 검색

- **Wikimedia Commons API**: 파일 페이지의 작가, 라이선스명, 라이선스 URL,
  원본 URL을 함께 수집합니다.
- **Openverse API**: `by`, `by-sa`, `cc0`, `pdm` 필터만 사용하고, 채택 직전
  원 제공자 페이지의 권리 정보를 다시 확인합니다.

두 소스 모두 검색 결과의 권리 정보가 절대적 보증은 아니므로 원본 파일 페이지를
증거로 남깁니다. Wikimedia 요청은 프로젝트와 연락 경로가 포함된 봇 User-Agent를
사용합니다.

### 자동 검색에서 제외

- 일반 웹 이미지 검색, Pinterest, Instagram, 블로그 CDN
- 라이선스 정보가 검색 결과에만 있고 원본 페이지에서 확인되지 않는 자료
- Unsplash 자동 배치 검색. Unsplash API는 비자동·진정성 있는 경험, CDN
  핫링크, 사진가와 Unsplash 크레딧, 선택 시 다운로드 트리거를 요구하므로 현재
  수동 에디터 검색에만 사용합니다.

## 3. 표준 도표와 유료 자료

정확한 표준 그림은 “온라인에서 보인다”와 “우리 사이트에 복제할 수 있다”가
다릅니다. SCA/WCR의 2016 Coffee Taster’s Flavor Wheel은 SCA가
`CC BY-NC-ND 4.0`과 별도 사용계약으로 안내합니다. 따라서 에이전트는 다음만
할 수 있습니다.

- SCA 공식 페이지를 참고 자료로 링크
- 원본의 색·배치·레이블을 복제하지 않은 Bean Wiki 고유 설명 도식 제안
- 자유 라이선스 커핑·향미 훈련 사진으로 실제 사용 장면 설명

공식 휠, WCR 렉시콘 PDF 페이지, 로고, 강의 슬라이드를 캡처하거나 닮게
재가공해서는 안 됩니다.

## 4. 에이전트 게이트

`scripts/research-article-images.mjs`는 검색과 권리 후보 선별만 수행하며 글을
고치지 않습니다. 다음 조건을 모두 충족한 후보만 accepted가 됩니다.

1. HTTPS 이미지와 HTTPS 원본 파일 페이지
2. 제작자와 라이선스명이 존재
3. 허용 라이선스 allowlist 통과
4. JPEG, PNG, WebP 비트맵
5. 명시된 검색 의도와 시각적 관련성

검색 점수는 정렬 보조일 뿐 게시 판정이 아닙니다. 실제 이미지를 사람이 확인한 뒤
`scripts/apply-article-image.mjs`로 선택하면 다음을 한 번에 생성합니다.

- `public/article-media/<slug>/...`: 자체 호스팅 파일
- `src/content/media/<slug>/...json`: 출처·라이선스·해시·확인일 증거
- 아티클의 `figure`: 대체 텍스트, 캡션, 제작자·라이선스·원본 링크

적용 도구는 글을 게시하거나 push하지 않습니다.

## 5. 캡션과 대체 텍스트

- **대체 텍스트**: 화면에 실제로 보이는 장면만 설명합니다.
- **캡션**: 본문에서 이 장면을 보는 이유를 한 문장으로 연결합니다.
- 새 글과 미디어 보강 대상으로 지정된 글은 frontmatter에
  `mediaMinimum: 3`을 선언하고, 서로 다른 설명 목적을 가진 figure를 최소
  3개 둡니다. 보통 1~2개 논리 문단 또는 한 섹션마다 한 장을 검토하되,
  이해를 높이지 못하는 장식 사진으로 숫자만 채우지 않습니다.
- 기존 글 전체를 한 번에 실패시키지 않습니다. 보강한 글부터
  `mediaMinimum` 게이트를 켜고, 남은 글은 미디어 커버리지 감사 목록으로
  순차 이관합니다.
- 산지, 품질, 인과관계는 이미지나 출처가 직접 뒷받침할 때만 씁니다.
- `향을 평가하는 커퍼`는 가능하지만, 사진만 보고 `Q 그레이더`나 특정 점수를
  단정하지 않습니다.

## 6. 게시 전 확인

- 증거 JSON과 이미지 파일, figure가 함께 존재하는가
- 출처 페이지와 라이선스 URL이 열리는가
- 이미지가 본문 이해를 실제로 높이는가
- 라이트·다크·모바일에서 캡션과 크레딧이 읽히는가
- `npm run build:content && npm run check-content`가 통과하는가

`npm run check-content`에는 `check-image-evidence`가 연결되어 있으므로 이미지,
증거 JSON, SHA-256, 아티클 figure 중 하나라도 누락되거나 서로 다르면 실패합니다.
`mediaMinimum`을 선언한 글은 figure 개수가 선언값보다 적어도 실패합니다.
