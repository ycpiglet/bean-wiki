# Bean Wiki 편집 기준 (SSOT)

> 원고의 품질 기준·측정 지표·작성 프로세스의 **단일 기준(SSOT)** 입니다.
> 사람과 AI 페르소나 패널(`.claude/agents/`) 모두 이 문서를 기준으로 원고를
> 쓰고, 평가하고, 게시 여부를 판정합니다. 디자인 기준은 [DESIGN.md](DESIGN.md),
> 참조 무결성은 `npm run check-content`가 담당합니다.

## 1. 문체 규칙

- **합니다체**. 단정 대신 조건과 경향: "~하는 경향이 있습니다", "참고 범위입니다".
- 수치는 **참고 범위 + 조건**으로만 제시 (예: "필터 기준 TDS 약 1.15~1.45%").
  절대 기준처럼 읽히는 문장 금지.
- 외래 용어는 첫 등장에서 한글(원어) 병기 (예: "발달 시간 비율(DTR)").
- 과대일반화·마케팅 수사·의인화 금지. 논쟁적 주제는 양쪽 관점을 한 문장씩.
- 한 문단 = 한 생각, 2~4문장. 본문에서 마크다운·HTML 문법 언급 금지.

## 2. 구조 규칙

- 첫 섹션은 개념 정의부터 시작하고, 난이도에 따라 아래 목표를 적용합니다.

| 난이도 | 목표 분량 | `<h2>` | 참고 자료 | 퀴즈 |
|---|---:|---:|---:|---:|
| 입문 | 1,600~2,200어절 | 6~8개 | 5~8개 | 4문항 |
| 중급 | 2,400~3,200어절 | 7~10개 | 8~12개 | 5문항 |
| 전문 | 3,000~4,500어절 | 8~12개 | 12~20개 | 6문항 |

- 권장 흐름은 요약 → 학습 목표 → 개념·원리 → 비교·사례 → 흔한 오해 →
  실습 → 용어 → 참고 자료 → 퀴즈입니다. 모든 글에 표를 억지로 넣지 말고
  관계를 실제로 더 선명하게 만들 때만 사용합니다.
- `fact`(핵심 한 줄): 문서 전체를 요약하는 검증 가능한 한 문장.
- 리치 블록 사용 기준: **표** = 3개 이상 항목의 값 비교, **콜아웃** = 본문 흐름
  밖의 강조(tip=요령, warn=흔한 실수/안전, note=구분 개념, important=핵심 원리),
  **토글** = 본문 이해에 필수가 아닌 심화.
- `related` 2~4개(양방향 고려), `tags` 3~6개(기존 태그와 겹치게).
- 난이도: 입문(전제 지식 불필요) / 중급(기본 문서 이해 전제) / 전문(실무 변수 조작).

## 3. 근거 규칙

- 기관 기준을 언급하면 기관명을 명시 (SCA, CQI, WCR 등)하고, 기준이 **개정 중인
  경우 그 사실 자체를 본문에** 적습니다 (예: CVA 전환).
- 확실도 표기: 확립된 사실(단정 가능) / 업계 통용 참고치(범위+"흔히") /
  논쟁·유동(양론 병기 또는 "논의가 진행 중").
- 웹 출처를 쓸 때 신뢰 순위: 표준 기관(SCA·CQI·WCR) > 학술 > 제조사 기술문서 >
  전문 매체 > 블로그. 블로그 단독 근거로 수치를 싣지 않습니다.
- 논문·서적·표준·보고서·강의는 `src/content/resources.ts`의 정규화된
  서지정보를 우선 재사용합니다. DOI, ISBN, 판·버전과 확인일을 기록합니다.
- 건강·가격·규정·SCA/CQI 표준처럼 변동성이 큰 글은 공공기관의 현재 원문을
  다시 확인하고 본문과 개정 이력에 검토일을 남깁니다.

## 4. 측정 지표 (루브릭)

6개 축 × 1~5점. 페르소나 리뷰는 각 축 점수 + 근거를 제출합니다.

| 축 | 5점 기준 | 1점 기준 |
|---|---|---|
| **정확성** | 검증 가능한 진술만, 오류 없음 | 사실 오류 존재 |
| **근거성** | 수치·주장에 조건/출처/헤지 완비 | 무근거 단정 |
| **명료성(한국어)** | 자연스러운 합니다체, 용어 병기 | 번역투·용어 혼란 |
| **구조** | §2 규칙 충족, 스캔 가능 | 섹션 구조 붕괴 |
| **완결성** | 난이도에 맞는 범위를 빠짐없이 | 핵심 개념 누락 |
| **중립성** | 경향·양론 처리 완벽 | 과대일반화·편향 |

### 게시 게이트

- **모든 축 ≥ 3점** 그리고 **평균 ≥ 4.0** → 게시 가능.
- 미달 시: 최저 축의 지적사항을 수정하고 해당 축만 재평가.
- 페르소나 간 점수가 2점 이상 갈리면 인터뷰어가 쟁점을 정리해 재검토.

## 5. 작성 프로세스 (하네스)

```
주제 선정 → 아웃라인(작가) → 초안(작가)
  → 패널 리뷰(병렬): 도메인 페르소나 2~3인 + 인터뷰어
  → 리서치 검증(research-librarian): 수치·기관 기준 웹 대조
  → 수정(작가) → 루브릭 게이트(§4)
  → 보강(media-curator → image-researcher): 위치 설계 → 이미지·캡션·라이선스 증거
  → draft: true 로 게시 → 사람 검토 → draft 해제(공개)
```

- 도메인 매핑: 로스팅→roaster, 추출/장비→barista, 센서리→q-grader,
  산지/생두/가공→farmer. 모든 문서에 interviewer + writer는 기본 포함.
- 스킬: `/write-article`(신규 작성 전체 하네스), `/review-article`(기존 문서
  채점·개선), `/enrich-article`(표·이미지·레퍼런스 보강).

## 6. 페르소나 명단

| 에이전트 | 역할 | 주 검증 영역 |
|---|---|---|
| `persona-roaster` | 로스터 | 로스팅 과학, 프로파일, 결점두 |
| `persona-barista` | 바리스타 | 추출 변수, 장비, 바 실무 |
| `persona-q-grader` | Q 그레이더 | 커핑, SCA/CVA 기준, 관능 용어 |
| `persona-farmer` | 생산자 | 재배, 품종, 가공, 산지 경제 |
| `persona-writer` | 작가/에디터 | 문체, 구조, 한국어 자연스러움 |
| `persona-interviewer` | 인터뷰어 | 근거 캐묻기, 쟁점 정리, 반례 |
| `research-librarian` | 리서치 사서 | 웹 검색·출처 신뢰도·수치 대조 |
| `media-curator` | 미디어 큐레이터 | 표 설계, 이미지 검색·라이선스, 리치 블록 |
| `image-researcher` | 이미지 리서처 | 허용 라이선스 사진·도해 검색, 권리 증거, 로컬 적용 |

## 7. 초보자 배치 운영

- 초보자 과정은 연결된 10편을 한 배치로 기획하고 한 편씩 공개합니다.
- 배치의 선수 개념, 중복 범위, 실습과 다음 글 연결을 먼저 고정합니다.
- 첫 배치의 순서와 개별 공개 게이트는
  [BEGINNER-CURRICULUM.md](BEGINNER-CURRICULUM.md)를 따릅니다.
- `npm run check:editorial`은 전체 참조·기본 구조와 현재 집필 대상의 분량,
  절 수, 참고 링크, 실습, 흔한 오해, 표·콜아웃 포함 여부를 검사합니다.
